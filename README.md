มีผู้ช่วย AI (กดปุ่มรูปหุ่นยนต์) แบ่งเป็น 3 อย่าง:
แชทคุยกับ AI ธรรมดา ถามเรื่องวางแผนงานได้
พิมพ์งานที่ยังไม่ชัดเจน/งานใหญ่ๆ ไป แล้วให้ AI ช่วยแยกเป็นงานย่อยให้ กดปุ่มเดียวเพิ่มเข้าลิสต์ได้เลย
ให้ AI อ่านงานทั้งหมดที่มีอยู่ แล้วบอกว่าควรทำอะไรก่อน-หลัง
เขียนด้วยอะไร
ตั้งใจเขียนแบบง่ายๆ ไม่ใช้เฟรมเวิร์กเลย:

HTML / CSS / JavaScript ธรรมดา ไม่มี React ไม่มี build tool อะไรทั้งนั้น
ฝั่งหลังบ้านใช้ Firebase (Hosting + Firestore) เพราะฟรีและ deploy ง่าย ไม่ต้องเช่าเซิร์ฟเวอร์เอง
ส่วน AI ใช้ Gemini API ของ Google (ฟรี ไม่ต้องผูกบัตร)
หน้าตาไฟล์ในโปรเจกต์
public/
├── index.html      → เฉพาะโครงหน้าเว็บ
├── css/styles.css  → ดีไซน์/สไตล์ทั้งหมด
└── js/app.js       → โค้ดที่ทำให้แอปทำงานได้จริง
ตอนแรกผมเขียนทุกอย่างรวมในไฟล์ index.html ไฟล์เดียวยาวเกือบ 4,000 บรรทัด (เพราะทำคนเดียว แก้ตรงไหนก็เจอง่าย ไม่ต้องเซ็ตอะไรซับซ้อน) พอเริ่มยาวมากขึ้นเรื่อยๆ ก็เลยแยก CSS กับ JS ออกมาเป็นคนละไฟล์ จะได้อ่านง่ายขึ้น

เรื่องที่อยากเล่า (จุดที่ตัดสินใจเอง ไม่ได้ทำตามตำราตรงๆ)
ทำไมไม่ใช้ React หรือเฟรมเวิร์กอื่น? เพราะทำคนเดียว ไม่มีทีม เพราะผมอยากลองฝืนใจตัวเองทำงานดูครับ ไม่จำเป็นต้องมีระบบ build ซับซ้อน แค่ HTML/CSS/JS ธรรมดาก็พอสำหรับสเกลนี้แล้ว แถม deploy ก็เร็วกว่าด้วยครับ

ทำไม API key ของ Gemini ถึงอยู่ในโค้ดเฉยๆ ไม่ซ่อนไว้หลังเซิร์ฟเวอร์? อันนี้จริงๆ ผมลองทำแบบ "ถูกต้อง" ก่อนแล้ว คือสร้าง Cloud Function ไว้เป็นตัวกลาง ไม่ให้ API key โผล่ในโค้ดหน้าเว็บเลย แต่พอลองทำจริงกลับเจอว่า Firebase บังคับให้ต้องผูกบัตรเครดิตก่อนถึงจะใช้ Cloud Function ได้ (แบบ Blaze) ซึ่งผมไม่สะดวกเรื่องนี้ เลยเปลี่ยนมาเรียก Gemini ตรงจากเว็บแทน

รู้อยู่ว่ามันมีความเสี่ยงอยู่บ้าง (ใครเปิดดูโค้ดก็เห็น key ได้) แต่ก็เลือกใช้ API key แบบที่ Google ล็อกไว้แล้วว่าเอาไปใช้ได้แค่กับ Gemini เท่านั้น ใช้ยิงบริการอื่นไม่ได้ ความเสี่ยงจริงๆ เลยมีแค่คนอื่นอาจแอบใช้โควต้าฟรีของผมเล่น ซึ่งสำหรับโปรเจกต์เล่นๆ ส่วนตัวคิดว่ารับได้ ดีกว่าต้องเสียเงินผูกบัตรเพื่อความปลอดภัยที่ไม่ได้จำเป็นขนาดนั้น

ถ้ามีเวลาอยากทำต่อ
ทำ backend จริงจังมาซ่อน API key ถ้าโปรเจกต์นี้ใหญ่ขึ้นกว่านี้
แยกไฟล์ app.js ให้เป็นไฟล์ย่อยๆ ตามหน้าที่ (ตอนนี้ยังรวมกันอยู่ไฟล์เดียว)
เขียน test ให้แอป (ตอนนี้ยังเทสด้วยมือเองล้วนๆ)
สิ่งที่ได้เรียนรู้จากการทำโปรเจกต์นี้
ลองต่อ AI API เข้ากับแอปจริงเป็นครั้งแรก และรู้ว่าจะสั่งให้ AI ตอบเป็น JSON แบบมีโครงสร้างต้องเขียน prompt ยังไง
รู้ว่าของที่อ่านมาจากตำรา/บทความ บางทีเอามาใช้จริงไม่ได้เป๊ะๆ (อย่างเรื่อง Cloud Function ต้องผูกบัตร) ต้องปรับแผนกลางทาง
ได้ลองทำ PWA จริงจังครั้งแรก รู้เรื่อง manifest, ไอคอนแอป, หน้า splash และปัญหาเล็กๆ น้อยๆ ที่เจอตอนเทสบนมือถือจริง (เช่น โลโก้ splash ที่ตั้งขนาดตายตัวไว้ ดันดูเล็กมากบนจอมือถือที่สูงๆ ต้องกลับมาแก้ให้ขยายตามจอ)
